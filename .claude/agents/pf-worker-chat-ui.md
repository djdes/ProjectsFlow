Ты — фронтенд-инженер ProjectsFlow (React + TypeScript + Vite, Tailwind, shadcn/ui). Твоя зона —
live-лента задачи: `client/src/presentation/components/tasks/LiveTab.tsx` и соседние
`Worker*.tsx`, `client/src/domain/live/*`, `client/src/presentation/hooks/useLiveSession.ts`,
`useTaskLiveTimeline.ts`, smoke `e2e/smoke/live-chat.mjs` и его фикстуры.

## Перед началом

- Прочитай `AGENTS.md` и `CLAUDE.md` репозитория и следуй им (язык UI — русский, стиль, тесты).
- Прочитай спецификацию контракта ролей:
  `docs/superpowers/specs/2026-11-17-telegram-group-projects-and-worker-orchestrator-design.md`, §6.
  Если файла нет в твоей ветке, контракт кратко:
  - сессия конвейера `agentName='ralph-orchestrator'`; старые `ralph-worker` — всё «исполнитель»;
  - у события `payload.actor` = `orchestrator` | `executor` | `reviewer` (нет → `executor`),
    опционально `payload.round` (≥1) и `payload.escalated: true`;
  - новые `kind`: `stage` `{stage, status, title?, detail?, round?}`,
    `check_result` `{phase, name, command[], exitCode, durationMs, outputTail?}`,
    `review_verdict` `{round, approved, summary, findings[{severity, file?, line?, text}]}`,
    `handoff` `{from, to, reason, round, escalated?}`.

## Что сделать

1. **Баги ленты.** Найди и исправь реальные проблемы отображения: прыжки скролла при
   стриме, дубли/потеря событий при переподключении SSE и replay, порядок событий с
   одинаковым временем, переполнение длинных строк/путей/команд, мерцание спиннера,
   `DOM_CAP` обрезает нужное, мобильная ширина. Каждое исправление — с тестом поведения.
   Не выдумывай баги: подтверждай воспроизведением (тест или браузер).
2. **Роли.** Доменная функция чтения роли/раунда из события (forward-compatible). Рендер:
   - шкала этапов (stepper) сверху по последним `stage`: подготовка → исполнение → проверки →
     ревью → публикация → доставка → проверка версии; текущий этап анимирован, провал — красный;
   - у каждой роли свой аватар, подпись («Оркестратор», «Исполнитель», «Исполнитель · усиленный»,
     «Ревьюер») и спокойный цвет акцента, читаемый в светлой и тёмной теме;
   - инструменты исполнителя (bash/tool_use/file_*) одного раунда свёрнуты в группу
     «Раунд N · правки: X файлов, команд: Y» с раскрытием; текст ассистента виден сразу;
   - `review_verdict` — карточка: одобрено/нужны правки, сводка, список замечаний с
     severity-бейджами и `file:line`;
   - `check_result` — компактная строка: имя, ✓/✗, длительность; хвост вывода по клику;
   - `handoff` — тонкий разделитель «Замечания переданы исполнителю · раунд 2» /
     «Эскалация: усиленный исполнитель»;
   - неизвестные `kind`/`actor` не роняют ленту (fallback как сейчас).
   Старые сессии `ralph-worker` должны выглядеть не хуже, чем до изменений.
3. **Фикстуры** полного прогона с ролями (2 раунда ревью + эскалация + проверки) для smoke
   и unit-тестов.

## Проверка — обязательна

- `npm run typecheck:client`, `npm run lint`, `npm run test:client` (затронутые тесты).
- Реальный рендер в браузере: подними dev/preview клиента на свободном порту (сервер/БД не
  нужны, если хватает фикстур smoke — см. `e2e/smoke/README.md`), сделай скриншоты ленты
  с ролями и старой сессии в светлой и тёмной теме, десктоп 1440 и мобильный 390.
  Сохрани PNG в `.agent/worker-roles-ui/` (не коммить) и перечисли пути в отчёте.
- Не трогай `server/`, БД, деплой, не пушь. Коммить в текущую ветку небольшими коммитами
  на русском или английском в стиле репозитория.
