# Смоук-тесты клиента

Быстрая проверка, что ключевые страницы ProjectsFlow открываются, ничего не падает и вёрстка
не разъезжается на десктопе и телефоне. Браузер — `playwright-core` из корневых
devDependencies, без `@playwright/test` и новых зависимостей. Сервер не нужен: все запросы
`/api/*` браузер получает из фикстур (`fixtures.mjs`), до настоящего бэкенда ничего не доходит.

## Запуск

```bash
npm run build:client && npm run test:smoke      # собранный client/dist на встроенном сервере
node e2e/smoke/run.mjs --url http://127.0.0.1:5173   # против уже запущенного клиента (Vite dev)
```

Полезные ключи:

| Ключ / переменная | Что делает |
| --- | --- |
| `--url <адрес>` / `SMOKE_URL` | гонять против запущенного клиента вместо `client/dist` |
| `--only inbox,board` / `SMOKE_ONLY` | только сценарии, у которых id или название содержит подстроку |
| `--full` / `SMOKE_FULL=1` | вся матрица сценария (тёмная тема, узкий телефон). По умолчанию — один десктоп и один телефон на сценарий: так в 1,5 раза быстрее |
| `--list` | показать все сценарии (id и вьюпорт) |
| `--verbose` | печатать все проверки, а не только упавшие |
| `--headed` | показать окно браузера |
| `CHROME_PATH` | путь к Chrome/Chromium, если автопоиск не нашёл |
| `SMOKE_ALLOW_SKIP=1` | нет браузера → предупреждение и выход 0 (так настроено в CI) |

Браузер ищется по порядку: `CHROME_PATH` → установленный Google Chrome → Microsoft Edge →
Chromium из кэша Playwright (`%LOCALAPPDATA%\ms-playwright\chromium-*`, `~/.cache/ms-playwright`).

Код выхода 1 — если упала хотя бы одна проверка (если первая страница не открылась в
четырёх сценариях подряд, прогон останавливается: приложение не грузится). При падении в `e2e/smoke/.artifacts/`
(в .gitignore, очищается в начале прогона) лежат скриншот момента падения (виновник
горизонтальной прокрутки обведён красным) и журнал сценария: проверки, последние сообщения
консоли, журнал мутаций, незамоканные эндпоинты. В CI папка прикладывается к упавшему
запуску как артефакт `smoke-artifacts`.

В dev-режиме React пишет в консоль больше предупреждений, чем сборка, — смоук считает
`console.error` ошибкой и там. Геометрия зависит от системных шрифтов (у приложения
системный стек), поэтому на Linux в CI и на Windows результаты по ширине могут отличаться
на пиксели.

## Что проверяется

Каждый сценарий идёт в новом контексте браузера: `locale ru-RU`, часовой пояс
Europe/Moscow, `reducedMotion: reduce`, свежие фикстуры. Вьюпорты: десктоп 1440×900,
телефон 390×844 (touch, DPR 2), узкий телефон 320×640 (touch). Тёмная тема —
`colorScheme: dark` и `pf-theme=system`; для ключевых страниц сценарий идёт в обеих темах.

Общие проверки на каждой странице:

- нет `pageerror` и `console.error` (кроме артефактов песочницы: оборванные SSE-стримы,
  HMR Vite, заблокированные внешние запросы, 401 на `/api/auth/me` без входа);
- нет экрана ошибки («Unexpected Application Error!», «Что-то пошло не так»,
  «Не удалось загрузить страницу»);
- ничего не шире экрана: у документа и `[data-pf-main]` нет прокрутки вбок, и ни один
  элемент не торчит за край экрана (у `html`/`body` стоит `overflow-x: clip`, поэтому
  слишком широкий блок молча обрезается — смоук ищет такие элементы сам и перечисляет их;
  ленты, которые листаются вбок намеренно, не в счёт);
- на телефоне видна нижняя навигация `nav[aria-label="Основная навигация"]`, её кнопки не
  ниже 44px.

Сценарии (`scenarios.mjs`):

| id | Что делает |
| --- | --- |
| `auth` | без входа `/` уводит на `/login`; формы `/login`, `/register`, `/forgot-password` |
| `inbox` | «Входящие» на десктопе: заголовок, «В работе» с полками «На утверждении» и «Вручную», «Очередь» с колонками проектов и всеми задачами |
| `inbox-filters` | `/` ставит курсор в поиск, поиск по части названия и счётчик «1 из N», Escape очищает, чип «Просрочено», «Сбросить фильтры» |
| `inbox-actions` | «Взять в работу» → `POST …/move {targetStatus: 'manual'}` и карточка во «Вручную»; «Принять» → `move` в `done` |
| `inbox-mobile` | «Входящие» на 390 и 320: переключатель `[data-pf-inbox-section-switch]` (`now`/`queue`, `aria-pressed`), разделы по одному со всеми карточками, тап по карточке открывает окно задачи, окно не шире экрана |
| `inbox-gestures` | телефон: свайп вправо по карточке очереди → `move {targetStatus: 'manual'}` и задача в «В работе»; долгий тап и бросок на «Готово» в доке (`[data-pf-dock-target]`) → `move` в `done`; лупа раскрывает поиск, крестик закрывает. Жесты — тач-события через CDP |
| `inbox-capture` | создание задачи при активном поиске и фильтре срока сохраняет её в черновики и показывает в очереди; поля мобильного ввода не меньше 16px |
| `task-create*` | исполнитель из выбранного сотрудника и обычного фильтра; календарный срок, ручная правка, восстановление черновика, ошибка и повтор загрузки участников |
| `quick-task-settings` | настройки под названием: дата по фильтру, шторки без blur-сохранения, отмена, два создания подряд, смена исполнителя; без перекрытия плавающим плюсом |
| `quick-workspace-switch` | шторка из мобильной шапки, текущее пространство, скелетон, изоляция задач после смены, видимая стрелка профиля; 390/320 px, обе темы |
| `board` | доска проекта: название, карточки, окно задачи по клику/тапу (на телефоне — не шире экрана), Escape закрывает |
| `task-properties` | новые подписи, «Создано» в меню, смена статуса и проекта, полные имена утверждающих, перестановка строк с сохранением в аккаунте |
| `task-personal-project` | перенос личной задачи из окна во «Входящих» в проект, повторное открытие и возврат в личные; desktop, 390 и 320px |
| `task-drawer-pickers` | вложенная шторка закрывается, оставляя окно задачи открытым; долгий тап сортирует свойства внутри окна; перенос убирает карточку с исходной доски |
| `mobile-nav` | телефон: кнопки нижней навигации ведут на «ИИ», «Профиль», «Входящие» (`aria-current`); бургер открывает меню, оно не шире экрана, проект из меню открывает доску |
| `overview` | обзор проекта: название, ссылка на доску, команда |
| `profile` | профиль: имя и email в форме |
| `telegram-connect*`, `telegram-status-retry` | подключение через бота без внешнего виджета; обычная и `tg://` ссылки; загрузка, подтверждение после возврата, ошибки запросов, повтор и истечение ссылки на desktop/390/320px |
| `workspace-settings` | настройки пространства: название, участники |
| `ai` | раздел ИИ: заголовок, поле ввода |
| `not-found` | несуществующий адрес → 404 |

Проверка со статусом «ждёт доработки» (○) видна в отчёте, но не роняет прогон: так
помечаются хуки, которых ещё нет в вёрстке (`t.expected`). Переключатель разделов «Входящих»
на телефоне уже в приложении, поэтому `INBOX_SECTION_SWITCH_REQUIRED = true` в `scenarios.mjs`:
нет кнопок `[data-pf-inbox-section-switch]` — проверка падает. Для прогона против старой
сборки флаг можно временно выключить.

## Фикстуры

Привязка Telegram проверяется с тестовым статусом и изолированным API: реальные аккаунты
не подключаются, сообщения не отправляются. SQL и миграцию можно отдельно проверить после
сборки сервера командой `node --env-file=.env scripts/verify-telegram-pairing.mjs`.
Скрипт использует временные таблицы для тестовых пользователей, проверяет одноразовость,
истечение, перевыпуск и отзыв ссылок, конфликт аккаунтов. Для проверки DDL создаётся и
сразу удаляется отдельная пустая таблица со случайным именем; данные приложения не меняются.

`workspace-isolation.mjs` дополняет основной набор сценариями трёх пространств:
команда → другая команда → личное → обратно, прямые ссылки, смена настройки из другой
вкладки, задержанные ответы, быстрый выбор исполнителей, ошибки загрузки и повтор.
Проверяются контекст HTTP/SSE, отсутствие прежних карточек и людей под скелетоном,
счётчики сроков и геометрия фильтров на 320/390 px в обеих темах. Ошибки HTTP разрешены
только для конкретных URL/кодов, намеренно заданных сценарием; остальные роняют прогон.

`fixtures.mjs` — детерминированные данные: админ «Анна Смирнова», командное пространство
(`kind: 'team'`, роль `owner`, `requireTaskApproval: true`), пять проектов и личные
«Входящие», трое коллег, задачи во всех нужных статусах (черновики, воркер, «Вручную», на
утверждении у коллег, выполненные) со сроками «вчера», «сегодня», «через неделю» и без
срока (даты считаются от сегодняшнего дня по Москве).

Роутер API:

- GET отвечает из состояния фикстур;
- POST/PATCH/PUT/DELETE пишутся в журнал (`t.journal.mutations`: метод, путь без `/api`,
  тело) и меняют состояние так, как сделал бы сервер (`move` меняет статус задачи и
  возвращает её и т.п.);
- стримы (`EventSource`, `…/stream`) обрываются;
- неизвестный GET получает `{}` с кодом 200 и попадает в список «Незамоканные эндпоинты» в
  конце отчёта (неизвестная мутация — `{ok: true}`). Если сценарий упал из-за `{}`, добавьте
  ответ в `getRoutes()` — формы ответов берите из `client/src/infrastructure/http/Http*.ts`.

Запросы на чужие домены блокируются, а `/api`, дошедший до встроенного статического сервера
(то есть не перехваченный в браузере), роняет прогон.

## Как добавить сценарий

Добавьте объект в массив `scenarios` в `scenarios.mjs`:

```js
{
  id: 'finance',                     // латиница: из него собираются имена артефактов
  title: 'Финансы проекта',
  matrix: [['desktop', 'light'], ['phone', 'light']], // вьюпорт × тема
  // auth: false,                    // для страниц без входа (/auth/me → 401)
  async run(t) {
    await t.goto('/projects/p-site/finance', {
      ready: () => t.page.getByText('Прибыль'),       // что должно появиться
      readyName: 'страница финансов',
    });
    await t.check('название проекта в крошках', () =>
      t.visible(t.page.getByText('Сайт клиники'), '«Сайт клиники»'));
    await t.pageChecks('финансы');   // экран ошибки, прокрутка вбок, нижняя навигация
  },
}
```

API сценария (`t`): `t.page` — страница Playwright; `t.state` — данные фикстур этого
прогона; `t.journal` — мутации и незамоканные эндпоинты; `t.goto(path, { ready })` и
`t.step(name, fn)` — жёсткие шаги (падение останавливает сценарий); `t.check(name, fn)` —
мягкая проверка (возвращает `true`/`false`); `t.skip(name, why)` — зависимая проверка, которую
не запускали; `t.expected(name, why)` — проверка, ждущая доработки приложения;
`t.pageChecks(label)` — общие проверки страницы; `t.boxFitsCheck(label, selector)` — окно
или меню не шире экрана; `t.visible`, `t.hidden`, `t.waitFor`, `t.assert`,
`t.waitForMutation` — помощники.
Ждите явных условий (`t.visible`, `t.waitFor`), а не фиксированных пауз.
