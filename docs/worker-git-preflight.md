# Обязательная проверка Git перед работой воркера

Проверка 30.10.2026 обнаружила, что патч `0008-worker-github-sync.patch`
добавлял правило fetch в каждый промпт, включая resume. Нативный запуск не
проверял выполнение этого правила. Блокировка checkout и прежний pre-push
защищали параллельную работу и историю целевой ветки, но новая feature-ветка
могла публиковаться без изменений, недавно появившихся в основной ветке.

[Патч 0009](ralph-runtime-fixes/0009-worker-git-preflight.patch) добавляет
обязательную проверку в локальный Ralph, поверх интеграций `0007` и `0008`.

## Поведение

- Перед запуском обычной, возобновлённой и одноразовой кодовой сессии рантайм
  получает эксклюзивную аренду checkout и выполняет fetch. Модель запускается
  после успешной проверки. Это распространяется и на редактор сайтов.
- При наличии GitHub выбирается его фактический remote. Серверный `origin`
  не заменяет проверку GitHub. Разные GitHub-репозитории среди remotes требуют
  разрешения неоднозначности. Для остальных Git-проектов используется upstream,
  затем `origin` либо единственный remote.
- Fetch обновляет remote-tracking refs всех веток с prune. Основная ветка
  определяется по удалённому symbolic HEAD: поддерживаются `main`, `master`
  и другие названия. Совпадение полученного SHA с удалённым HEAD проверяется.
- HEAD должен включать основную ветку, существующую удалённую рабочую ветку
  и настроенный upstream выбранного remote. Отставание, расхождение,
  удалённый upstream, неизвестный HEAD, ошибки доступа или сети блокируют запуск.
- Проверка оставляет HEAD, индекс, staged/unstaged и untracked файлы на месте.
  Для отставшего checkout требуется безопасная интеграция с сохранением правок
  или отдельный актуальный worktree. Автоматические merge/rebase/reset не выполняются.
- Временные `pre-commit` и `pre-push` повторяют fetch и проверку: изменения
  удалённой ветки во время работы блокируют коммит или push. Хуки оператора
  сохраняются в цепочке. Настройка hooksPath действует только в процессе воркера.
- Прежний task pre-push сохраняет запреты чужих коммитов, публикации исходных
  пользовательских изменений и переписывания удалённой истории. Проверка fetch
  добавлена и в этот исполняемый файл: уже запущенные task-воркеры получают её
  при следующем обращении к своему pre-push.
- Host-публикация редактора сайтов отдельно проверяет синхронизацию перед
  работой, сохранением результата и отправкой, после выхода дочерней модели.

Git-процессы работают без интерактивных запросов авторизации, с ограничением
ожидания 60 секунд на команду. Ошибки содержат причину блокировки; credentials
в URL и GitHub-токены скрываются. Недоступность remote останавливает работу.

Задания `TextOnly` без инструментов, snapshot-папки без `.git` и локальные
репозитории без remotes сохраняют свой режим. Для пустого удалённого репозитория
разрешён первый коммит. Неопределённый каталог задания с инструментами блокируется.

## Установка и активация

В текущем `C:\www\ralph` изменения установлены с сохранением чужих
незакоммиченных правок. Обратный `git apply --reverse --check` патча проходит.
Патч содержит только изменения этой задачи, включая тесты.

На другой установке сначала применяются интеграции `0007` и `0008`, затем:

```powershell
git apply --check <полный-путь-к-0009-worker-git-preflight.patch>
git apply <полный-путь-к-0009-worker-git-preflight.patch>
```

Параллельные задачи создают новый процесс и заново импортируют модуль, поэтому
новые запуски получают защиту без остановки активных задач. Уже загруженные
в основном процессе диспетчера модули для inline/serial-путей обновятся при
штатном перезапуске после завершения активной работы. Перезапуск не выполнялся.
Начало уже работающей сессии невозможно проверить задним числом.

GitHub не отдаёт `djdes/PFLoopDispatch` текущей учётной записи: fetch через
GitHub CLI возвращает `Repository not found`. Поэтому изменения Ralph
сохранены воспроизводимым патчем в ProjectsFlow; синхронизация и публикация
самого PFLoopDispatch не объявляются успешными.

## Проверки

В Windows PowerShell 5.1 выполнены:

- `worker-git-preflight.tests.ps1` — 29 проверок на временных настоящих Git/bare
  репозиториях: свежий и отставший `master`, feature-ветка от `main`, расхождение,
  изменения общей ветки, удалённый upstream, ошибка fetch, неизвестная основная
  ветка, выбор GitHub, сохранность файлов и индекса, хуки оператора, обычный push,
  запрет коммита/push после изменения main и запрет запуска обеих кодовых моделей.
- `worker-git-policy.tests.ps1` — 38 проверок существующих ограничений и аренды.
- `codex-engine.tests.ps1` — 53 проверки рантайма.
- `codex-task-session.tests.ps1` — 22 проверки новых и возобновлённых сессий.
- `worker-github-sync.tests.ps1` — 18 проверок обязательного правила в промпте.

Тесты не запускают настоящую модель и не публикуют изменения в чужие репозитории.
Синтаксис затронутых PowerShell-файлов проверен штатным AST parser.
