# Индикатор обновления платформы

В верхней части приложения появляется компактный индикатор, когда workflow
`djdes/ProjectsFlow / deploy.yml / main` ожидает запуска или выполняется.
Этапы берутся из GitHub Actions и шагов текущей попытки: проверки, сборка,
установка и подтверждение публикации. Проценты по времени не рассчитываются.

Настройка сервера: `PLATFORM_DEPLOY_PROJECT_ID` — проект самой платформы.
Репозиторий проекта обязательно должен быть `djdes/ProjectsFlow`.
Используется существующее GitHub-подключение диспетчера или разрешённая ему
делегация. Дополнительные токены в браузер не передаются. Использование делегации
фиксируется как `deployment_status` один раз на запуск и владельца подключения.

`GET /api/platform/deployment` требует пользовательскую сессию и отдаёт только
состояние обновления. Клиент не выбирает репозиторий, workflow или подключение.
Один общий кэш и один выполняющийся запрос обслуживают все вкладки и аккаунты.
Интервал обновления — 10 секунд; скрытые вкладки приостанавливают опрос.

Vite записывает полный `GITHUB_SHA` в `client/dist/build.json`. Этот файл входит
в существующий артефакт выкладки. Успех подтверждается одновременно успешным CI
и совпадением версии установленного артефакта. При несовпадении показывается
подтверждение публикации; сетевой сбой сохраняет последний этап с пометкой
о временно недоступном статусе.
Версия для кнопки перезагрузки выдаётся только после этого подтверждения,
в том числе клиентам предыдущей сборки.

Установленная новая версия предлагает кнопку «Обновить». Автоматической
перезагрузки нет. Если текущая вкладка уже использует эту версию, индикатор
успешного завершения исчезает через восемь секунд. Ошибку можно скрыть;
следующий запуск появляется снова. Анимация отключается системным уменьшением
движения и настройкой анимации в приложении.
