# Автономный C# воркер в Telegram

Дополнение направляет сообщения с обращением к существующему боту из одного явно
настроенного группового чата в отдельный проект CSharpFixer. Аккаунт ProjectsFlow,
выбор проекта и подтверждения от сотрудника не требуются. Создание выполняется от
владельца существующей привязки `telegram_group_owners`; проверка прав и доступности
воркера пространства сохраняется. Все другие чаты используют обычный маршрут.

На сервере включаются три переменные (секрет не хранится в Git):

```text
CSHARP_FIXER_CHAT_ID=<отрицательный числовой Bot API chat ID>
CSHARP_FIXER_PROJECT_ID=<UUID отдельного проекта>
CSHARP_FIXER_SIGNING_KEY=<случайный общий секрет не короче 32 символов>
```

HMAC связывает проект, реального Telegram-отправителя, чат, сообщение, топик и хеш
исходного текста. Заголовок чата не даёт разрешений. Подписанные метаданные сохраняются
в задаче и не выводятся в сообщениях Telegram. Внешний CSharpFixer проверяет подпись,
хранит журнал и отвечает исходному автору тем же ботом. Серверный `taskOrigins` для
этого маршрута не регистрируется, чтобы два независимых отправителя не дублировали ответ.

Обычный текст принимается сразу. Альбом сохраняется в устойчивом черновике и ждёт
15 секунд тишины; дополнительные части известного источника принимаются без повторного
упоминания. Задача создаётся в backlog и переводится в todo только после сохранения
вложений. Ошибка загрузки оставляет запрос вне рабочей очереди для проверки оператором,
не задавая сотруднику вопросов. Поздние части уже запущенного альбома сохраняются
в черновике и журнале, с уведомлением о необходимости проверки оператором.

Сама реализация исправлений, независимое ревью, публикация, доставка и проверка
установленной версии находятся в отдельном репозитории `djdes/CSharpFixer`. В первом
пилоте включён C#Config; исполнитель и отдельный ревьюер используют gpt-6.1-sol / low.
Новый Telegram poller или webhook не создаётся. Возможность бота читать сообщения
в чате включает владелец; тестовое сообщение отправляет он сам.
