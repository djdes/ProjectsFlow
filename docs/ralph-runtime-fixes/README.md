`0003-task-session-continuation.patch` — коммит Ralph `9d4f35b`:
сохранение UUID Codex на задачу и продолжение через `exec resume <UUID> -`.
Ключ включает аккаунт диспетчера, адрес API, проект, задачу и проверенную рабочую папку;
короткие задания ИИ остаются одноразовыми. Каждый запуск использует свежую аренду MCP
и текущие настройки guard. Блокировка файла исключает два одновременных продолжения.

Патч содержит модуль, 19 проверок и `codex-task-session.integration.patch` — только
изменения точек интеграции с установленным локальным native runtime. Этот runtime
содержит более ранние незакоммиченные изменения оператора; они не включены в коммит.
На другом таком checkout после применения `0003` нужно отдельно выполнить
`git apply --check codex-task-session.integration.patch`, затем `git apply` этого файла.
В текущем `C:\www\ralph` обе части уже установлены; обратная проверка патча проходит.
Для активации точек интеграции нужен перезапуск диспетчера после завершения активных работ.
Доступа на push в `djdes/PFLoopDispatch` у текущей учётной записи по-прежнему нет.

В композере по умолчанию выбрано «Продолжить сессию»; «Новая сессия» прикрепляет
маркер сброса к пользовательскому промпту. Маркеры от агентов игнорируются.
Сессии старых запусков с `--ephemeral` восстановить нельзя: первый запуск после
обновления создаёт сохраняемый контекст, дальнейшие промпты его продолжают.
Проверено отдельными процессами настоящего Codex: второй запрос вспомнил значение
из первого сообщения без повторной передачи значения.

`0004-queue-start-priority.patch` — коммит Ralph `28794ab`:
плановая полная синхронизация проектов уступает очередь задачам между проверками
проектов. До публикации полного результата прерванная синхронизация восстанавливает
предыдущие workspace claims, запреты KB и сигнатуру; проверенный runtime сохраняется.
Следующая попытка синхронизации откладывается на 30 секунд. Проверки identity,
готовности задачи, рабочих часов и бюджета остаются обязательными.

В простое `Wait-WithAiPoll -WakeForWorkerQueue` проверяет очередь с интервалом
пять секунд. Лёгкая discovery-проверка читает задачи только известных проверенных
проектов с открытыми задачами, исключает ожидание утверждения и уточнения.
Для рабочих часов и исчерпанного бюджета раннее пробуждение выключено.
Пять секунд — интервал обнаружения, а не обещание полного старта: предпроверки
и отдельный выполняющийся запрос синхронизации требуют дополнительного времени.
Первичная проверка проектов при старте и явная синхронизация оператора выполняются полностью.

Установка в существующий native runtime: применить `0004`, затем проверить и применить
`dispatch-queue-priority.integration.patch` аналогично `0003`. Основной `dispatch.ps1`
локально содержит чужие незакоммиченные изменения; в патч включены только новые точки
интеграции. Сохранять PowerShell-файлы с UTF-8 BOM; активировать перезапуском
диспетчера после завершения всех его активных заданий.

Проверки: `dispatch-queue-priority.tests.ps1` (25 проверок с виртуальными часами,
прерыванием настоящей функции синхронизации и восстановлением claims),
`dispatch-ai-poll.tests.ps1`, `dispatch-startup.tests.ps1`,
`workspace-isolation.tests.ps1` (40 проверок). Локальный случай 22 октября:
плановый sync шёл с 17:26:43 до 17:29:38 без изменений — 175 секунд до опроса очереди.

`0005-worker-task-images.patch` (Ralph `9204756`) добавляет `worker-attachments.ps1`, восемь проверок
и отдельный `worker-attachments.integration.patch` для установленного native runtime.
MCP получает проверенный корень проекта и сохраняет вложения в
`node_modules/.cache/projectsflow-attachments/` внутри него. Для git-проектов этот
каталог дополнительно исключается через локальный `.git/info/exclude`; snapshot
уже исключает `node_modules`. Путь через junction в чужой checkout отклоняется.
Промпт требует открыть изображения задачи и комментариев через `view_image`/Read,
сопоставляя их с HTML-позицией и `commentId`. Наличие имени файла не считается просмотром.

Для этого нужен MCP 0.25.1 из текущего `mcp-server/`: локальный диспетчер раньше
использовал 0.24.0 без материализации файлов. Собрать и упаковать пакет из исходников,
установить в отдельный runtime-каталог, заменить только путь MCP entry в локальном
конфиге. В текущей установке используется
`C:/www/ralph/mcp-runtime/0.25.1/node_modules/@projectsflow/mcp-server/dist/index.js`.
Глобальный MCP другого пользователя сохраняется. После применения integration-патча
перезапустить диспетчер, когда нет активных заданий.

Пакет можно подключить без перезапуска существующего диспетчера: он читает MCP-конфиг
заново при выдаче каждой аренды. В текущем базовом конфиге указаны
`PROJECTSFLOW_WORKSPACE_ROOT=.` и относительный `PROJECTSFLOW_ATTACHMENT_DIR=node_modules/.cache/projectsflow-attachments`.
MCP наследует рабочую папку Codex, закреплённую в проверенном проекте. Это проверено
контрактом с реальным дочерним MCP-процессом и настоящим вложением. После будущего
перезапуска integration-патч дополнительно задаёт абсолютные пути отдельно для проекта.
MCP сам исключает автоматический кэш из git, проверяя отсутствие перенаправлений
в `.git/info/exclude`. Уже запущенные MCP-процессы сохраняют прежнюю версию до следующего запуска.

MCP дополнительно проверяет границу `PROJECTSFLOW_WORKSPACE_ROOT` при записи,
включая `saveTo`, переходы `..`, symlinks/junctions и прямую запись в `.git`.
Контрактные тесты запускают настоящий MCP через stdio: картинки из описания и
комментария сохраняются на диск и остаются native image-блоками; выход из проекта
отклоняется. Тесты статусов сохраняют запрет отправлять задачи воркеру через MCP.
Проверено скачивание настоящего скриншота задачи и его чтение отдельным Codex
в read-only режиме: модель правильно назвала «Входящие» и требования к подписям аватаров.
