# Управление пользователями

Раздел «Администрирование → Пользователи» доступен только системным администраторам.
Каждый изменяющий API-запрос также проверяет права на сервере.

- «Изменить»: имя, почта для входа, удаление фотографии профиля. Пустое имя,
  некорректная или занятая почта отклоняются. При смене почты старые ссылки
  сброса пароля отзываются. Свой профиль сразу обновляется в интерфейсе.
- «Тариф и срок»: Бесплатный, Прайм или ВИП; дата и время окончания в часовом
  поясе устройства, бессрочная выдача или 30 дней с текущего момента.
  Срок можно менять и без смены тарифа. Прошедшая дата завершает подписку;
  Бесплатный очищает даты. Использование пробного тарифа не сбрасывается.
- «Сделать админом / Снять админа»: системные права. Снять собственные права
  нельзя. Сервер повторно проверяет администратора внутри транзакции;
  параллельные изменения не могут оставить систему без администратора.
- «Удалить»: требуется ввести почту выбранного пользователя. Свой аккаунт
  удалить нельзя. Действие необратимо через интерфейс.

Удаление закрывает аккаунт и обезличивает строку профиля: почта заменяется
техническим уникальным адресом, имя — «Удалённый пользователь», пароль,
аватар и Telegram-привязка очищаются. Сессии и ссылки сброса пароля удаляются,
токены агентов отзываются, GitHub-подключение удаляется, делегации отключаются,
назначение пользователя диспетчером проектов снимается. Старой почтой можно
зарегистрироваться заново — это будет другой аккаунт без доступа к прежним данным.

Строка пользователя сохраняется с `deleted_at` для ссылок из истории и проектов.
Проекты, задачи, комментарии и владение проектами/пространствами сохраняются;
вход и выдача тарифа удалённому аккаунту запрещены. При необходимости
администратор управляет сохранёнными проектами через свои системные права.

Нужна миграция `db/173_user_deletion.sql`. Её применяет штатный деплой перед
перезапуском сервера. `PATCH /api/admin/users/:id/plan` принимает
`subscriptionExpiresAt`: ISO-дата, `null` для бессрочного тарифа или отсутствие
поля для совместимой выдачи на 30 дней. Даты ограничены диапазоном MariaDB
`TIMESTAMP` (до 19 января 2038 года).
