# Управление пользователями

Раздел «Администрирование → Пользователи» доступен только системным администраторам.
Каждый изменяющий API-запрос также проверяет права на сервере.

- «Изменить»: имя, почта для входа, удаление фотографии профиля, отвязка Telegram. Пустое имя,
  некорректная или занятая почта отклоняются. При смене почты старые ссылки
  сброса пароля отзываются. Свой профиль сразу обновляется в интерфейсе.
- «Тариф и срок»: Бесплатный, Прайм или ВИП; дата и время окончания в часовом
  поясе устройства, бессрочная выдача, 30 дней с текущего момента или продление
  на 7/30/365 дней от даты в поле (если она в будущем). Над формой — текущий тариф
  и сколько дней осталось. Срок можно менять и без смены тарифа. Прошедшая дата завершает подписку;
  Бесплатный очищает даты. Использование пробного тарифа не сбрасывается.
- «Сделать админом / Снять админа»: системные права. Снять собственные права
  нельзя. Сервер повторно проверяет администратора внутри транзакции;
  параллельные изменения не могут оставить систему без администратора.
- «Удалить»: диалог сначала показывает сводку (GET `/api/admin/users/:id/deletion-preview`),
  затем требует ввести почту пользователя. Свой аккаунт и другого администратора
  удалить нельзя (сначала снять права). Действие необратимо через интерфейс.

## Что делает удаление

Правила — `server/src/domain/user/userDeletion.ts` (`planUserDeletion`), одни и те же для
сводки и для самого удаления. Удаление выполняется в одной транзакции под блокировкой
администратора и пользователя; снимок данных перечитывается внутри неё.

- **Блокировка.** Командное пространство, где пользователь владелец, есть другие активные
  участники и нет второго владельца, удалять запрещено: нужно назначить другого владельца
  в настройках пространства (можно через «Войти как»). Команда не теряет данные молча.
- **Удаляется навсегда:** пространства, где пользователь владелец и других активных
  участников нет (в том числе личное), со всеми проектами, задачами, комментариями и
  файлами; его «Входящие» во всех пространствах.
- **Переходит команде:** в остальных пространствах пользователь выходит из участников,
  его задачи (включая корзину) и владение его проектами получает владелец пространства;
  задачи в чужих «Входящих» возвращаются их владельцу. Если пользователь был записан
  владельцем пространства со вторым владельцем — запись переходит второму. Активные
  делегирования задач на него отзываются.
- **Очищается:** сессии, ссылки сброса пароля, токены агентов (отзыв), GitHub-подключение,
  делегации GitHub-токена, роль диспетчера, Telegram (поля профиля, групповые чаты и выбор
  пространства для чатов), личные подключения ИИ, уведомления, письма рассылок в очереди
  (отменяются — в них снимок старой почты), просмотры задач, токены действий из писем.
- **Остаётся:** строка профиля с `deleted_at`, обезличенная (техническая почта, имя
  «Удалённый пользователь», без пароля, аватара, Telegram и тарифа). Авторство комментариев,
  истории и ленты сохраняется; лента показывает «Удалённый пользователь». Старой почтой
  можно зарегистрироваться заново — это будет другой аккаунт без доступа к прежним данным.
  Журнал расхода ИИ не трогается (биллинг-история).

Нужна миграция `db/173_user_deletion.sql`. Её применяет штатный деплой перед
перезапуском сервера. `PATCH /api/admin/users/:id/plan` принимает
`subscriptionExpiresAt`: ISO-дата, `null` для бессрочного тарифа или отсутствие
поля для совместимой выдачи на 30 дней. Даты ограничены диапазоном MariaDB
`TIMESTAMP` (до 19 января 2038 года).
