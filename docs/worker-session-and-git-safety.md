# Продолжение сессии и безопасные коммиты воркера

При разборе задачи `46d8217a` 23 октября обе попытки имели одинаковый UUID
Codex: контекст продолжался. LIVE создаёт отдельную запись исполнения для
каждого запуска процесса; она не означает новый контекст модели. Теперь native
runtime явно пишет в ленту, подтверждено ли продолжение прежнего контекста.
Сообщение появляется после проверки `thread.started`, а не по намерению клиента.

Кнопка остановки учитывает работающую LIVE-попытку, даже если задача уже
перенесена на утверждение. Сервер проверяет права редактора и существование
активного процесса; условный SQL повторяет проверку при записи. Завершённую
задачу остановить нельзя. Запрос и подтверждение остановки показаны раздельно.

Причина списка из 45 файлов в этой задаче — диапазон `headBefore..HEAD`,
включавший изменения, подтянутые из `main`. Сам коммит `4836ac49` менял один
`Sidebar.tsx`: +4/-34. Этот случай подтверждает неверное приписывание изменений;
сам по себе он не доказывает перезапись 45 файлов воркером.

Серверная защита:

- Автоматическая привязка через агентский API требует `[первые 8 символов taskId]`
  в сообщении коммита. Явная ручная привязка остаётся доступной.
- Финальные изменения новой попытки собираются из помеченных коммитов задачи,
  привязанных после её запуска. GitHub возвращает файлы с учётом пагинации.
  Счётчики суммируют правки этих коммитов, не общий diff ветки.
- При недоступности проверки LIVE показывает понятное сообщение. Общий diff
  рабочего checkout не используется как замена. Snapshot-проекты без Git
  продолжают передавать файловые изменения обычным способом.
- Исторические привязки и сохранённые отчёты автоматически не удаляются.

Native runtime (`docs/ralph-runtime-fixes/0007-worker-session-and-git-safety.patch`):

- Блокировка checkout на всё время процесса предотвращает одновременную запись
  разными задачами или диспетчерами в одну папку. Разные проекты работают параллельно.
- Временный `pre-push` проверяет исходящую историю: разрешены только коммиты этой
  задачи, сохранение удалённой истории и отсутствие файлов, изменённых до запуска.
  Неизвестные исходные изменения требуют разбора, а не автоматического включения.
- Настройки hooks действуют только в дочернем процессе. Постоянная конфигурация
  Git сохраняется; существующий `pre-push` требует явного объединения политик.
  Остальные hooks вызываются через исходные файлы.
- Workspace guard запрещает обход через `--no-verify`, изменение политики,
  force-push и разрушительное разрешение конфликтов.
- Промпт продолжения сохраняет контекст и требует добавлять конкретные файлы,
  интегрировать актуальную удалённую ветку и повторять затронутые проверки.
- Native-отчёты и автоматическая привязка также фильтруются по отметке задачи.

В установленном runtime изменения модуля и workspace guard применяются к новым
дочерним воркерам без перезапуска родительского диспетчера. Обновлённые функции
его локальных отчётов загружаются при следующем штатном перезапуске, после
завершения активных заданий. Серверная проверка LIVE и привязок действует
независимо от версии родительского процесса.

Проверки: тесты прав и гонки остановки, SQL-ограничения, DOM кнопки в review,
отбор коммитов и файлов LIVE, недоступность GitHub, реальная пагинация HTTP,
native CLI resume с сохранённым UUID, настоящий push в тестовый bare-репозиторий,
блокировка второго воркера, чужого коммита, исходных изменений и переписывания
удалённой истории. Проверки не запускают пользовательские задачи и не отправляют
сообщения в Telegram.
