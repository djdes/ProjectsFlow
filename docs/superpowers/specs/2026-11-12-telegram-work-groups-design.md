# Рабочие Telegram-группы пространства и автоопределение id группы

Дата: 2026-11-12
Статус: утверждён владельцем (реализация — PR «рабочие группы + добавить из соседних»)

## Задача (от владельца)

1. В настройках пространства — добавлять дополнительные рабочие Telegram-группы. В них
   @ProjectsFlow_Bot работает как обычно (отвечает, перефразирует, создаёт задачи). Если задачу
   пишет человек без привязанного Telegram — бот даёт короткую пошаговую инструкцию со ссылками:
   зарегистрироваться, быть в пространстве, привязать Telegram.
2. Id группы определяется автоматически или есть чёткая инструкция, как его узнать.

Решения владельца (2026-11-12): человек без привязки получает кнопку «Подключиться» (персональная
ссылка в личке бота), вступает **сразу редактором**, бот реагирует в группе **как сейчас**
(упоминание, ответ боту, голосовые).

## Что уже есть

- Бот в группе реагирует на `@ProjectsFlow_Bot`, ответ на своё сообщение и голосовые (spec
  2026-06-09 mention-gate). Привязанный участник создаёт задачи «как отправитель» (spec
  2026-07-08). Непривязанный → во «Входящие» владельца группы (`telegram_group_owners`, `/start`
  в группе) или подсказка «владелец, отправьте /start».
- У пространства одна «основная» группа для сводок (`workspace_assignee_digest_settings.
  telegram_group_chat_id`), id вводится руками; есть «Получить название» (getChat).
- Привязка Telegram — только из профиля: `t.me/<bot>?start=connect_<token>` (db/163).

## Решение

### Модель

- **Рабочая группа** — строка `workspace_telegram_groups (tg_chat_id PK, workspace_id, title,
  added_by_user_id, created_at)`. Одна группа — рабочая максимум у одного пространства. Только
  командные пространства (`kind='team'`): в личный хаб нельзя приглашать.
- Основная группа сводок рабочей автоматически **не** становится: её может менять любой участник,
  а рабочая группа даёт вход в пространство. В карточке рабочих групп есть кнопка «Сделать
  рабочей» для основной группы.
- Группы, которые не рабочие, ведут себя как раньше (владелец группы, «Входящие» владельца).

### Подключение группы (автоопределение id)

- Кнопка «Подключить группу» (владелец/руководитель) → `POST /api/workspaces/:id/telegram-groups/link`
  → одноразовый код (32 байта, в БД — SHA-256, TTL 30 минут) → ссылка
  `https://t.me/<bot>?startgroup=wg_<code>`. Telegram предлагает выбрать группу, добавляет бота
  (если его там нет) и присылает в группу `/start@<bot> wg_<code>`.
- Код принимается только от администратора группы (`getChatAdministrators`: creator/administrator);
  иначе «подключить может только администратор», код не гаснет. Так рядовой участник чужой группы
  не перехватит её задачи в своё пространство.
- Бот по коду привязывает группу к пространству, отвечает «✅ Группа «…» подключена к
  пространству «…»». Код гаснет. Группа уже рабочая у другого пространства → «уже подключена к
  другому пространству, сначала отключите её там» (имя чужого пространства не раскрываем).
- Тот же механизм с `purpose='main'` у поля основной группы сводок: «Подключить автоматически»
  заполняет chat_id и название (права — как у карточки сводок: любой участник).
- Страница, пока открыт диалог, раз в 3 секунды перечитывает список и сама показывает новую
  группу.
- Запасные пути: команда `/id` (в группе бот отвечает id и название; в личке — подсказка);
  когда бота добавили в группу вручную, он здоровается и пишет id группы (если за 3 секунды группу
  не подключили кодом — чтобы не дублировать сообщение). Ручной ввод id: сервер проверяет getChat
  (бот в группе) и что Telegram добавляющего — администратор группы.
- Переезд группы в супергруппу (`migrate_to_chat_id`) переносит привязку рабочей группы и основной
  группы сводок на новый id.

### Бот в рабочей группе пространства «W»

Гейт упоминания не меняется. После него, перед конструктором задач (текст и голосовые):

| Отправитель | Поведение |
| --- | --- |
| Telegram привязан, участник W | как сейчас; задачи без проекта — во «Входящие» W (группа учтена в `linkedWorkspaceIds`) |
| Telegram не привязан | инструкция из 3 шагов + кнопка «🚀 Подключиться» (`t.me/<bot>?start=wj_<id>`) |
| Telegram привязан, не участник W | «вы ещё не в «W»» + кнопка «✅ Вступить в «W»» (callback `wj:<id>`) |

- Текст сообщения запоминается в `telegram_group_onboardings` (одна открытая запись на
  группа+человек; новые сообщения дописываются; повтор той же доставки Telegram не дублирует).
  Полная инструкция — не чаще раза в 10 минут, иначе короткое «📝 Запомнил».
- Кнопки работают только для автора: чужое нажатие получает подсказку.
- `/start wj_<id>` в личке:
  - Telegram уже привязан → участник W? «Готово»; нет → добавляем редактором;
  - не привязан → персональное приглашение в W (роль editor, без почты, 7 дней) и сообщение
    со ссылкой `…/invite/<token>`: «зарегистрируйтесь или войдите и нажмите «Принять», затем
    «Подключить Telegram»».
- Принятие такого приглашения на сайте **не привязывает Telegram**: ссылку мог открыть кто угодно
  (её могли переслать), и привязка чужого Telegram к аккаунту отдала бы ему уведомления и действия
  от имени владельца. Поэтому после «Принять» сайт показывает «Подключить Telegram» — обычную
  ссылку подключения (`connect_`, db/163) для владельца аккаунта. Когда Telegram привязан этой
  ссылкой, бот создаёт ждавшие задачи — только если подключился тот самый Telegram, что писал в
  группе, и человек уже участник W. Если у аккаунта уже тот же Telegram — задача создаётся сразу;
  другой Telegram — задачу не создаём и говорим об этом.
- Действует, пока группа рабочая у этого же пространства: отключение группы (или перенос в другое
  пространство) закрывает ждущие подключения и отзывает их непринятые приглашения; кнопки и
  приглашение после этого не впускают.
- Кого руководитель удалил из пространства (`workspace_member_removals`), тот не возвращается сам
  кнопкой «Вступить» или приглашением бота — только обычным приглашением руководителя (оно и
  снимает отметку).
- Кнопки работают только для автора сообщения (сверка Telegram-id), токены одноразовые.
  Публичных ссылок-приглашений в группе нет.

## Данные (db/181)

`workspace_telegram_groups`, `telegram_group_link_tokens (token_hash PK, workspace_id, purpose,
created_by_user_id, expires_at)`, `telegram_group_onboardings (id CHAR(12) PK, tg_chat_id,
workspace_id, tg_user_id, tg_username, tg_first_name, sender_name, group_title, pending_text,
last_source_key, status pending|invited|completed|cancelled, invite_id, prompted_at, expires_at)`,
`workspace_member_removals (workspace_id, user_id, removed_at)`.

## Слои

- domain: `telegram/WorkGroup.ts` (типы, `isOnboardingPayload`, тексты не здесь).
- application/telegram: порты `TelegramWorkGroupRepository`, `TelegramGroupOnboardingRepository`;
  use-cases `ManageTelegramWorkGroups` (list/link/addManual/remove/bindFromCode/migrate),
  `TelegramGroupOnboarding` (prompt/privateStart/joinCallback/completeFromInvite).
- infrastructure: Drizzle-репозитории, `getChatMember` в `HttpTelegramClient`.
- presentation: роуты в `workspaces/routes.ts`; вебхук — новые ветки `/start wg_`, `/start wj_`,
  `wj:`, `/id`, приветствие, миграция чата.
- client: `TelegramWorkGroupsCard` в настройках пространства, кнопка «Подключить автоматически»
  у основной группы, сообщение о привязке Telegram на странице приглашения.
