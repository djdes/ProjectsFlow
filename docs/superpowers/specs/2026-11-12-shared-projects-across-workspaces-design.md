# Один проект в нескольких пространствах: доступ пространств и видимость задач

Дата: 2026-11-12
Статус: утверждён владельцем (реализация — отдельный PR после «рабочих групп»)

## Задача (от владельца)

Любой проект можно использовать одинаково в разных пространствах. Правая кнопка на проекте →
«Доступ пространств» → галочки доступных пространств. Владельцы и руководители настраивают, кто
чьи задачи видит. Пример: в новом пространстве «Офис» менеджеры пишут свои задачи по проекту; эти
задачи видны в «Программистах» (статусы и т.д.), а задачи, созданные в «Программистах», в «Офисе»
не видны. Решение владельца: правила **по пространствам + персональные по людям**.

## Подходы

1. **Выбран.** Один проект, несколько пространств; задача помнит пространство создания; правила
   видимости. Проект один (база знаний, колонки, репозиторий, воркер).
2. «Зеркальный» проект в «Офисе», чьи задачи подмешиваются в доску основного. Проще с правами, но
   это два проекта с разными настройками — не «использовать одинаково».
3. Общий проект без происхождения задач: нельзя «Офис → Программисты в одну сторону».

## Модель

- **Основное пространство** проекта — `projects.workspace_id` (как раньше: в нём проект создан,
  его правила воркера/колонок/сверки коммитов).
- **Подключённые пространства** — `project_workspace_access (project_id, workspace_id, task_scope,
  visible_from JSON, created_by_user_id, created_at)`. Строка для основного пространства хранит
  только его правило видимости (доступ основному даёт `projects.workspace_id`).
- **Происхождение задачи** — `tasks.origin_workspace_id` (NULL = основное). Происхождение, которое
  больше не подключено к проекту, считается основным.
- **Правило пространства** `task_scope`: `all` (все задачи), `own` (созданные в этом
  пространстве), `selected` (свои + из `visible_from`). По умолчанию основное — `all`,
  подключённое — `own`.
- **Правило человека** — `project_member_task_visibility (project_id, user_id, task_scope
  all|mine|selected, visible_from JSON)`: заменяет правила пространств для этого человека в этом
  проекте. `mine` — только задачи, где он автор или ответственный.

### Кто что видит

Человек U видит проект P, если он (не скрытый галочкой) участник основного или подключённого
пространства. Роль в проекте — лучшая из ролей в этих пространствах (автор проекта — owner).

Задачу T проекта P в пространстве W человек U видит, если выполняется одно из:
1. U — автор или ответственный T;
2. U — автор проекта или owner/lead основного пространства (они настраивают правила);
3. проект не общий (нет подключённых пространств) — как раньше;
4. происхождение T входит в набор правила человека, если оно есть, иначе — в набор правила W.

По прямой ссылке (без контекста W) — объединение по всем пространствам P, где U участник.

### Где задача «рождается»

Сайт — текущее пространство запроса (`X-Workspace-Id`), если оно подключено к проекту; Telegram —
пространство рабочей группы; иначе — единственное пространство проекта, где автор состоит; иначе
основное. Старые задачи — основное (NULL).

### Чьи правила

Приёмка — пространство происхождения задачи (задачи «Офиса» принимает руководитель «Офиса», если
там включена приёмка). Воркер, колонки, сверка коммитов, публичная ссылка — основного.

## Интерфейс

- Меню проекта в боковой панели и на странице проекта: «Доступ пространств…». Видят и меняют
  автор проекта и owner/lead основного пространства.
- Окно: раздел «Пространства» — основное (отмечено, не снимается) + пространства, где вы
  owner/lead (командные). Для отмеченных — «Видит задачи: все / только свои / свои и из
  выбранных». Раздел «Люди» — все, у кого есть доступ, с правилом «по пространству / все / только
  свои / из выбранных пространств».
- В подключённом пространстве проект в списке со значком «общий» и подписью основного
  пространства. На карточках задач из других пространств — бейдж с названием пространства.
- Скрыть проект от конкретного участника подключённого пространства — существующие галочки
  доступа в настройках этого пространства (exclusions по `workspace_id`).

## Где применяется (сервер)

Доступ к проекту (`findForProject`, списки проектов пространства, аудитория `listByProject`),
доска (`ListTasks`), чтение/изменение/удаление задачи (`taskAuthorization`), комментарии и
вложения (через проверки задачи), списки «Входящих» (mine/others/member/awaiting-reply/approvals),
поиск, уведомления (получатели и пространство уведомления), живые обновления (аудитория и фильтр
SSE по пространству), сводки пространства, Telegram (списки и сводки), MCP (через use-cases).
Для проектов без подключённых пространств — быстрый путь без изменений поведения.

## Отключение и перенос

Отключение пространства — его задачи остаются в проекте и считаются задачами основного
(происхождение обнуляется). Удаление пространства — каскадом убирает подключения. Перенос проекта
(существующая функция) — подключение нового основного пространства удаляется.

## Данные (db/18x)

`project_workspace_access`, `project_member_task_visibility`, `tasks.origin_workspace_id` +
индекс `(project_id, origin_workspace_id)`.

## Тесты

Чистые функции видимости (все комбинации правил, автор/ответственный, owner/lead, устаревшее
происхождение). Репозитории/use-cases: доступ через подключённое пространство, скрытие галочкой,
доска в двух пространствах, прямая ссылка, списки «Входящих», поиск, аудитория уведомлений,
происхождение при создании (сайт/Telegram/MCP), приёмка по происхождению, проект без подключений —
без изменений.
