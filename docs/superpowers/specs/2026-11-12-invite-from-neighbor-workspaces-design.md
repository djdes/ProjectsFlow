# «Добавить из соседних»: быстрые приглашения людей из других пространств

Дата: 2026-11-12
Статус: утверждён владельцем (реализация — PR «рабочие группы + добавить из соседних»)

## Задача (от владельца)

В настройках пространства при добавлении пользователей — кнопка «добавить из соседних»:
выпадающий список, чтобы легко и быстро отправлять приглашения.

## Что уже есть

- Приглашение по почте (`WorkspaceInviteForm`): по одному адресу, роль редактор/наблюдатель,
  скрытые проекты (owner/lead). Доставка (`DeliverWorkspaceInvites`): письмо + уведомление на
  сайте с «Принять» + Telegram с кнопкой «Принять приглашение».
- `GET /api/me/shared-members` — только активное пространство (для приглашения в него же
  бесполезно: там одни участники). Межпространственный `listSharedUsers` есть только в
  репозитории.

## Решение

### Сервер

- `GET /api/workspaces/:id/invite-candidates` — кто может приглашать (owner/lead/editor),
  только командное пространство. Ответ:
  `{ candidates: [{ userId, displayName, email, avatarUrl, hasTelegram, workspaces: [{id, name, icon}], invited }] }`.
  Кандидаты — все участники пространств, где состоит приглашающий, кроме него самого и текущих
  участников целевого пространства. `workspaces` — общие с приглашающим пространства (откуда
  человек «сосед»). `invited` — есть непринятое и неистёкшее приглашение на его почту.
- `POST /api/workspaces/:id/invites/neighbors` `{ userIds: string[1..50], role: 'editor'|'viewer' }` →
  для каждого id сервер проверяет, что человек действительно сосед (иначе `not_neighbor`), берёт
  почту из базы и создаёт адресное приглашение тем же `CreateWorkspaceInvite` (права, скрытые
  проекты редактора, дедуп, доставка — без изменений). Ответ:
  `{ results: [{ userId, status: 'queued'|'reused'|'member'|'not_neighbor'|'error' }] }`.
- Use-cases: `ListWorkspaceInviteCandidates`, `InviteNeighbors` (application/workspace); запрос
  кандидатов — `DrizzleWorkspaceRepository.listInviteCandidates`.

### Клиент

- В форме приглашения — кнопка «Из соседних пространств» (иконка людей). Окно (`Dialog`):
  поиск по имени/почте/пространству, список с галочками (аватар, имя, почта, чипы пространств,
  значок Telegram, бейдж «приглашён» — такие строки неактивны), выбор роли, кнопка
  «Пригласить (N)». После отправки — тост «Отправили N приглашений: почта, сайт, Telegram»,
  событие `pf:workspace-invites-changed` (список ожидающих обновится).
- Порт `WorkspaceRepository.listInviteCandidates/inviteNeighbors`, HTTP-адаптер, компонент
  `NeighborInviteDialog` в `presentation/components/project/`.

## Тесты

node:test: кандидаты (исключены участники и сам приглашающий; флаг `invited`; viewer — 403;
личный хаб — запрет), пакетное приглашение (чужой id → `not_neighbor`, участник → `member`,
повтор → `reused`). Клиент: фильтр поиска и выбор (чистая функция).
