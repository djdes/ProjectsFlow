# Перетаскивание задач в полки «На утверждении» и «Вручную» во «Входящих»

Дата: 2026-08-05
Статус: согласовано, ждёт плана реализации

## Задача

Во «Входящих» над колонками живут две полки:

- **«Вручную»** (`InProgressShelf`, статус `manual`) — «чем я занят прямо сейчас»;
- **«На утверждении»** (`ApprovalShelf`, статус `pending_approval`) — очередь приёмки (db/150).

Положить задачу в «На утверждении» перетаскиванием нельзя: полка не является целью дропа.
Единственный путь туда — нажать «выполнено» на своей задаче, после чего сервер сам подменяет
`done` → `pending_approval` для того, кто не вправе принимать работу. Связь между галочкой
«выполнено» и появлением карточки в чужой очереди неочевидна.

Полка «Вручную» цель дропа уже принимает (`useDroppable`, `data: { type: 'work', status:
'manual' }`), рендерится всегда, кроме режима выделения.

## Решение

Одна точка изменения — `client/src/presentation/components/tasks/AssignedToMeBlock.tsx`.

### 1. Полка «На утверждении» становится целью дропа

Тем же приёмом, что и полка «Вручную»:

```
useDroppable({ id: 'approval-shelf', data: { type: 'approval' } })
```

В `handleDragEnd` добавляется ветка `data.type === 'approval'`, которая зовёт

```
taskRepository.move(projectId, taskId, {
  targetStatus: 'pending_approval',
  beforeTaskId: null,
  afterTaskId: null,
})
```

и затем `refresh()` + `onChanged?.()` — как это делает существующий `setWorkStatus`.

### 2. Кто и что может бросать

Дроп разрешён, только если выполнены оба условия:

- перетаскиваемая задача назначена текущему пользователю (`assignee.userId === user.id`);
- её статус ещё не `pending_approval`.

Чужую задачу (вкладка «Для всех», доска сотрудника) бросить на приёмку нельзя: «сдать работу
за другого» — не то действие, которое стоит отдавать жесту.

Предикат выносится в чистый экспортируемый хелпер `canSendToApproval(task, currentUserId)`
рядом с прочими чистыми хелперами блока — чтобы покрыть тестом без React.

Механика запрета: блок уже держит перетаскиваемую карточку в состоянии `activeDrag`, поэтому
родитель вычисляет `canDrop = activeDrag ? canSendToApproval(activeDrag.item, user.id) : false`
и передаёт его в `ApprovalShelf` пропом. Полка отдаёт этот флаг в `useDroppable({ disabled:
!canDrop })` — недоступная цель не попадает в коллизии, не подсвечивается и не может принять
дроп. Приём уже используется в этом файле (`useDroppable({ …, disabled: data === null })`).

### 3. Серверных изменений не требуется

Три причины:

1. `MoveTask` пропускает явный `targetStatus: 'pending_approval'` без подмены —
   `TaskApprovalService.resolveTargetStatus` вмешивается только когда запрошен `done`.
   Значит жест работает одинаково для исполнителя и для руководителя: оба «сдают работу».
2. `taskStatusSchema` уже принимает `pending_approval` — попутный фикс из задачи о кастомных
   колонках (`28f14af7`). До него этот перенос отбивался бы валидацией.
3. Уведомление принимающему (`notifyApprovalRequested`) шлётся внутри `MoveTask` при переходе
   в `pending_approval` — отдельного вызова не нужно.

### 4. Полка «Вручную»

Код не меняется: цель дропа там уже есть. Проверяется вручную на проде; если обнаружится
поломка — чинится отдельно как баг, а не в рамках этой работы.

### 5. Ошибки

Отказ сервера (заморозка задачи на приёмке, недостаток прав) показывается тостом с текстом
ошибки, после чего список перечитывается — карточка не остаётся визуально в неправильном месте.

## Границы

Гейта «приёмка включена» в коде не будет: полка `ApprovalShelf` рендерится только когда
`approvalTasks.length > 0 || isApprover`, а `isApprover` требует
`currentWorkspace.requireTaskApproval === true`. Там, где приёмка выключена, полки нет —
значит нет и цели дропа.

## Что сознательно не делаем

- **Обратную тягу** (вытащить карточку из «На утверждении» перетаскиванием). Выход из полки
  остаётся за существующими кнопками: «Принять» и «Вернуть в работу» — руководителю,
  «Отозвать» — исполнителю. Задача на утверждении заморожена для всех, кроме принимающего,
  поэтому обратный дроп потребовал бы отдельного пути отзыва.
- **Кнопки/меню «перенести в…»** на карточке — выбран жест перетаскивания.
- **Массовые действия** над выделением.

## Тестирование

- Юнит-тест на `canSendToApproval`: своя задача → true; чужая → false; уже на утверждении →
  false.
- Ручная проверка на проде: перетаскивание своей задачи в «На утверждении» и в «Вручную»;
  попытка перетащить чужую задачу с вкладки «Для всех» (полка не подсвечивается).
